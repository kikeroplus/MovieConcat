## 1. MovieChecker（フォルダ分けロジック）のロジック要約

- CLI ツール（`--root` でフォルダ指定、`--apply` を付けない限り dry-run）。GUI なし。
- 対象: JPG (`.jpg` `.jpeg`) と動画 (`.mp4` `.mov` `.avi` `.mkv` `.wmv` `.m4v` `.webm`)。
- `root.rglob("*")` で **再帰的に全階層** を走査する（`JPG/` `Movies/` の中も再スキャン対象）。
- 動画の分類名は `ffprobe` で取得した `width` / `height` から決定:
  - 横長: `H{width}x{height}`
  - 縦長: `V{width}x{height}`
  - 正方形: `S{width}x{height}`
  - 取得失敗: `Unknown`
  - **回転メタデータ（rotate / displaymatrix）は考慮していない**（ffprobe の生の width/height をそのまま使う）。
- 移動先で同名ファイルが既にある場合は **上書きせず** `_001`, `_002` の連番を付けてリネームして退避する。
  dry-run 中に同じ移動先に複数ファイルが集まる場合も衝突を予約管理して回避する。
- 削除は行わない。移動のみ（`shutil.move`）。
- 除外フラグ・履歴・Undo・状態ファイルの概念はない。

## 2. concat-videos（結合ロジック）のロジック要約

- CLI ツール（カレントディレクトリを起点に実行、`-s/--sort` でソート指定）。GUI なし。
- 対象拡張子: `.mp4` `.mov` `.mkv` `.avi` `.m4v` `.webm` `.mts` `.m2ts`（**`.wmv` は含まれない**）。
- `find_folders_with_videos` でカレント配下を **再帰的に** 探索し、動画を含むフォルダ全てを結合対象にする。
- ソートモード: `date-asc`（既定・更新日時 `st_mtime` 昇順）/ `date-desc` / `name`（`str.lower()` の単純文字列比較、**自然順ではない**）。
- 各フォルダで動画が 1 本でもあれば単独リマックス（`-c copy` で拡張子だけ揃える）まで実行する。
- 結合方式の判定は **コーデック・解像度・音声形式の一致比較をしていない**。判定基準は「2 本目以降の動画の**先頭フレームが I フレームかどうか**」のみ:
  - 全ファイルが I フレーム始まり → `concat_via_ts`（各ファイルを MPEG-TS にリマックスしてから `concat:` プロトコルでストリームコピー結合。H.264/HEVC の bitstream filter 自動適用、必要なら `aac_adtstoasc`）
  - 1 本でも非 I フレーム始まり、または TS 経由結合が失敗 → `normalize_and_concat`（全ファイルを先頭ファイルの解像度・fps に scale/pad して `libx264 -crf 16 -preset slow` + `AAC 320k` で再エンコードしてから結合）
  - **解像度やコーデックが混在していても、全ファイルが I フレーム始まりなら `concat_via_ts` に進んでしまう**（不正な結合結果になり得る）。
- 出力先: 実行ディレクトリ直下に `merged_{フォルダの相対パスをアンダースコア連結}_{実行時分秒タイムスタンプ}.{拡張子}`。**毎回別名なので上書きは発生しない**。
- `merged_` から始まるファイルは結合対象から除外するフィルタがある（過去の出力を再取り込みしないため）。
- 進捗表示は ffmpeg の標準出力をリアルタイムにそのまま流すのみ（`-progress pipe:1` によるパーセンテージ算出はしていない）。キャンセル機構もない。
- 中間ファイルは `tempfile.TemporaryDirectory()` で作成し `with` ブロック終了時に自動削除（正常終了時のみ確認済み。中断時の挙動は未検証）。

## 4. 結論・移植方針

- 既存 2 ツールから **そのまま流用できるロジックはほぼない**（対象拡張子・分類名・判定方式・出力先が軒並み異なる）。
- 移植というより **CLAUDE.md 仕様に基づく新規実装** とし、既存コードは以下の点のみ参考にする:
  - `ffprobe` の呼び出しパターン（`subprocess` + JSON パース）
  - TS 経由結合が「非 I フレーム始まりでの映像フリーズ」を回避する手法だったという知見（ただし CLAUDE.md 仕様は concat demuxer + `-c copy` を採用しているため、**この手法は Phase 4 で問題が起きた場合の代替候補としてのみ留意**する。まずは仕様通り concat demuxer 方式で実装する）
  - `NOTES.md` に記録された、動画結合で past に踏んだ落とし穴（DTS 非単調増加、非 I フレーム結合点でのフリーズ、早送り再生）は、判定 A（完全一致・`-c copy`）実装時に同様の問題が起きないか実機確認する際の着眼点として使う
- ディレクトリ名について: `CLAUDE.md` 2 章はプロジェクト直下を `MovieManager/` と表記しているが、実際の作業フォルダ名は `MovieConcat` のまま。フォルダ名はリネームせず、`MovieConcat/` 直下に `main.py` `core/` `gui/` `docs/` を配置する（仕様書中の呼称と実フォルダ名の違いのみで、ロジック上の差分ではない）。
